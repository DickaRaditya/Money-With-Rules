# Vercel deployment

Import the existing [Money-With-Rules repository](https://github.com/DickaRaditya/Money-With-Rules) into Vercel. Use these project settings:

| Setting                                         | Value                       |
| ----------------------------------------------- | --------------------------- |
| Production branch                               | `main`                      |
| Framework preset                                | Next.js                     |
| Root directory                                  | `apps/web`                  |
| Include source files outside the Root Directory | Enabled                     |
| Node.js                                         | 24.x                        |
| Output directory                                | Framework default (`.next`) |

`apps/web/vercel.json` installs dependencies from the root lockfile with `npm ci`, then runs the root build. That build compiles Solidity and exports the ABI before building Next.js. It never deploys contracts or signs transactions. Do not use a static export or add a catch-all rewrite: the application needs its Next.js API routes.

See Vercel's [monorepo guide](https://vercel.com/docs/monorepos) and [shared source configuration](https://vercel.com/docs/monorepos/monorepo-faq).

## Environment variables

Set the following in Vercel before building, for the environments you intend to use:

| Variable               | Value                                                                |
| ---------------------- | -------------------------------------------------------------------- |
| `NEXT_PUBLIC_CHAIN_ID` | `84532`                                                              |
| `NEXT_PUBLIC_RPC_URL`  | `https://sepolia.base.org` or a public Base Sepolia RPC              |
| `SERVER_RPC_URL`       | Base Sepolia RPC; private provider credentials are allowed only here |
| `APP_ORIGIN`           | The exact HTTPS origin of this environment, without a trailing slash |

For the first deployment, use the assigned production domain as `APP_ORIGIN` once Vercel shows it, then redeploy. Use that domain for wallet sign-in. Preview deployments require their own exact `APP_ORIGIN`; an unrelated preview URL is deliberately rejected by the origin checks.

The frontend can be published before the blockchain and database are configured. With chain `84532`, the committed local `31337` deployment is not used: the UI displays the missing-contract state and does not pretend that payments work. Never use `localhost` or local Hardhat addresses for the public deployment.

After deploying the contracts to Base Sepolia, add all of these together and rebuild:

- `NEXT_PUBLIC_TOKEN_ADDRESS`
- `NEXT_PUBLIC_REGISTRY_ADDRESS`
- `NEXT_PUBLIC_VAULT_ADDRESS`
- `NEXT_PUBLIC_DEPLOYMENT_BLOCK`

Alternatively, commit the actual Base Sepolia deployment output generated by `npm run deploy:base` and leave the address overrides empty. Set `BASE_SEPOLIA_RPC_URL` and a dedicated testnet `DEPLOYER_PRIVATE_KEY` in the root `.env`, fund that wallet with faucet ETH, then run `npm run compile` and `npm run deploy:base`. Deploy contracts from a trusted local environment; **do not add `DEPLOYER_PRIVATE_KEY` to Vercel**.

For profiles, merchant applications, and signed-wallet sessions, run `supabase/migrations/001_initial.sql` in the hosted Supabase project and set `SUPABASE_URL` plus `SUPABASE_SERVICE_ROLE_KEY` in Vercel. The service-role key is server-only and must never have a `NEXT_PUBLIC_` prefix. Without those credentials, protected metadata features report that storage is unavailable.

`NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID` is optional. If supplied, allow the deployment origin in WalletConnect. Injected browser wallets work without it.

Changing `NEXT_PUBLIC_*` variables requires a new deployment because Next.js includes them at build time. Configure secrets through Vercel, not in committed files. Keep `.vercel/` and real `.env*` files untracked.

## Verify the live deployment

After Vercel reports Ready, open the production URL and check navigation plus the missing-configuration or live-contract state. Run the existing HTTP checks against the exact `APP_ORIGIN`:

```powershell
$env:SMOKE_ORIGIN = 'https://YOUR-PROJECT.vercel.app'
npm run test:http
```

The checks cover all 12 pages, unauthenticated API access, cross-origin rejection, and invalid request validation. They do not prove that an external wallet, hosted Supabase, or testnet transaction is configured; verify those separately when their credentials and contracts are available.
